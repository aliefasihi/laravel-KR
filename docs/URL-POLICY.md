# سیاست URL

نویسنده: علی فصیحی (Ali Fasihi)

## خلاصه

| نوع | الگو | نسبت به وردپرس |
|---|---|---|
| دسته‌بندی | `/product-category/{path}/` | **دقیقاً همان URL** (با اسلش آخر و اسلاگ فارسی) |
| محصول | `/p/{brand}-{sku}` | جدید — 301 از URL قدیمی |
| برند | `/brand/{slug}` | جدید — 301 از URL قدیمی |
| مقاله | `/blog/{slug}` | جدید (ASCII) — 301 از URL قدیمی |
| بلاگ | `/blog` | جدید |
| تگ‌ها و آرشیوهای وردپرس | — | 301 به نزدیک‌ترین دسته یا 410 |

## قواعد

1. **دسته‌ها دست نمی‌خورند.** مسیر decode‌شده‌ی وردپرس در `categories.path` ذخیره می‌شود و `Category::url()` آن را مثل وردپرس encode می‌کند (hex کوچک) و اسلش آخر را نگه می‌دارد. پیشوند از `KHANEH_CATEGORY_PREFIX` می‌آید و باید با تنظیمات پیوند یکتای سایت فعلی یکی باشد.
2. **اسلاگ محصول ساختنی است، نه تایپ‌کردنی:** `ProductSlug::make(brand.slug, sku)`.
   - فقط `a-z`، `0-9` و `-`؛ ارقام فارسی به لاتین تبدیل می‌شوند
   - SKU بدون حرف یا عدد لاتین رد می‌شود ← قبل از ایمپورت باید SKUها اصلاح شوند
   - SKU باید یکتا و پایدار باشد؛ برای محصول متغیر، SKU محصول والد ملاک است
3. **تغییر SKU یا اسلاگ برند** ← `ProductUrlChanged` ← `Redirect::point()` ← URL قدیمی 301 می‌شود. زنجیره‌ها خودکار جمع می‌شوند.
4. **اسلش آخر:** فقط دسته‌ها اسلش آخر دارند؛ بقیه بدون اسلش. فرم اشتباه یک 301 می‌گیرد (`CanonicalTrailingSlash`). قانون حذف اسلش در `public/.htaccess` عمداً حذف شده است.
5. **حروف بزرگ** در URL محصول به نسخه‌ی lowercase ریدایرکت می‌شود.
6. **هر 404** در درخواست GET، قبل از نمایش، جدول `redirects` را چک می‌کند. مقایسه با `UrlPath::hash` انجام می‌شود، پس فرم encode و decode و `ي/ی` و `ك/ک` یک کلید دارند.
7. **هر URL قدیمی دقیقاً یک hop** تا صفحه‌ی 200 فاصله دارد. قبل از لانچ، کل لیست کراول فعلی روی استیجینگ تست می‌شود.
8. URLهای query وردپرس (`/?p=123`، `/?page_id=`، `/?product=`، `/?product_cat=`) با کلید `?p=123` در `redirects` ذخیره می‌شوند.
