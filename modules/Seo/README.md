# Seo
ریدایرکت‌های legacy، متا، سایت‌مپ.

- جدول `redirects` با کلید `UrlPath::hash` (فرم encode/decode و ي/ی همه یک کلید)
- هر GET که به 404 برسد اول این جدول را چک می‌کند (هندلر استثنا) — پس /p/ قدیمی هم کار می‌کند
- `Redirect::point()` زنجیره‌ها را جمع می‌کند: هر URL قدیمی دقیقاً یک hop
- URLهای query وردپرس (`/?p=123`) با کلید `?p=123` ذخیره می‌شوند
- status 410 برای صفحاتی که عمداً حذف شده‌اند (تگ‌ها، آرشیوها)

## پیشنهاد ریدایرکت برای آدرس‌های قدیمی جامانده (`Support/LegacyProductMatcher`)
وقتی آدرس قدیمی محصولی که در جدول ریدایرکت نیست ۴۰۴ می‌شود (مثلاً `/product/gk-sarina-gk701107-6/`):
1. کد کالا مستقیم در کاتالوگ پیدا می‌شود. کلمه‌های آدرس هم با همان موتور جستجوی سایت جستجو می‌شوند.
2. به هر نامزد امتیاز داده می‌شود:
   - **۱.۰** وقتی SKU محصول در آدرس قدیمی باشد.
   - حداکثر **۰.۹۵** برای سهم کلمه‌های آدرس که در نام، برند یا SKU پیدا شده‌اند.
3. امتیاز بالاتر از `suggest_min_score` (پیش‌فرض ۰.۶) یک ردیف در **سئو ← پیشنهادهای ریدایرکت** می‌سازد.
   - تعداد بازدیدها هم شمرده می‌شود.
   - با «تأیید ۳۰۱» یا «محصول دیگر»، ریدایرکت با `Redirect::point` ساخته می‌شود.
4. اگر `SEO_AUTO_REDIRECT_SCORE=1` تنظیم شود، تطابق دقیق کد کالا بدون بررسی ۳۰۱ می‌شود.
5. صفحه‌ی ۴۰۴ بهترین تطابق‌ها را با عنوان «شاید دنبال این‌ها بودید» نشان می‌دهد؛ برای هر ۴۰۴، نه فقط محصولات.

نتیجه‌ی جستجو برای هر آدرس یک روز کش می‌شود، تا ربات‌ها نتوانند با تکرار یک آدرس بار ایجاد کنند.
پیشوند آدرس محصولات قدیمی در `modules/Seo/config.php` تنظیم می‌شود (`legacy_product_prefixes`).
