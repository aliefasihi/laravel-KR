# Crm — مخاطبان و صندوق فرم‌ها
نویسنده: علی فصیحی (Ali Fasihi)

پایه‌ی CRM خانه رمانتیک: هر کسی که فرمی پر کند، نظر بنویسد، عضو خبرنامه شود، حساب بسازد یا خرید کند، یک **مخاطب** است و هر کارش یک **فرم دریافتی**.

## پنل ← ارتباط با مشتری
- **صندوق فرم‌ها** (`/admin/inbox`): یک تب برای هر فرم (تماس با ما، خبرنامه، نظر محصول، نظر مقاله…) با ستون‌های همان فرم، شمارنده‌ی جدیدها، مشاهده (خودکار «خوانده‌شده»)، وضعیت (جدید/خوانده‌شده/رسیدگی شد/هرزنامه) و یادداشت داخلی، فیلتر تاریخ، خروجی CSV هر تب (با BOM، درست در اکسل).
- **مخاطبان** (`/admin/contacts`): یک نفر برای هر موبایل (یا ایمیل)، لینک به حساب مشتری، برچسب (گروهی هم)، یادداشت، عضویت خبرنامه، اولین آشنایی و کمپین ورود (utm)، و **سابقه‌ی همه‌ی فرم‌هایش**. خروجی CSV.
- تنظیمات ← **فرم‌ها و مخاطبان**: پیامک فرم‌های تازه به شماره‌های همکاران، برای فرم‌های انتخاب‌شده.

## برای ماژول‌ها
```php
Forms::define(new FormDefinition('consult', 'درخواست مشاوره', ['name' => 'نام', 'mobile' => 'موبایل', 'need' => 'نیاز']));
Forms::record('consult', $data, ['name' => …, 'mobile' => …, 'email' => …], subject: $model);
```
`record()` هیچ‌وقت خطا نمی‌دهد (فرم اصلی نمی‌شکند). پارامترهای `utm_*`/`gclid` اولین بازدید در session نگه داشته و با فرم ذخیره می‌شوند.

## جدول‌ها (برای CRM آینده)
- `contacts`: name, mobile (یکتا), email (یکتا), customer_id, source, tags, notes, newsletter_*, utm, first/last_seen_at
- `form_submissions`: form, contact_id, subject (morph), data (json), status, note, page_url, ip, utm, handled_by/at
